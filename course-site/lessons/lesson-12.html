Google Analytics — מה קורה אחרי הקליק

לדעת מה קורה אחרי הקליק — ולוודא שכל המרה נמדדת נכון.

בסוף השיעור תדעו

  • להקים GA4 עם אירועים ואירועי מפתח (Key events)
  • לבדוק מדידה בזמן אמת לפני קמפיין
  • להבין למה Meta, גוגל ו-Analytics מראים מספרים שונים
השורה התחתונה

כל אוטומציה של הפלטפורמות לומדת מההמרות שאתם מודדים. מדידה שבורה = המערכת לומדת את הדבר הלא נכון.

איך GA4 חושב

ב-GA4 הכול הוא אירוע: צפייה בעמוד, גלילה, לחיצה, שליחת טופס. אירועים שחשובים לעסק מסמנים כ-אירועי מפתח (Key events) — זה מה שבעבר נקרא ״המרות״.

  • התקנה: דרך Google Tag Manager (מומלץ) או התג של גוגל ישירות.
  • אירועים אוטומטיים: צפיות, גלילות, קליקים יוצאים (Enhanced measurement).
  • אירועים שאתם מגדירים: generate_lead, purchase, click_whatsapp, call.
  • עמוד תודה אחרי טופס הוא הדרך הכי פשוטה ואמינה למדוד ליד.

הפיקסל וה-API של הפלטפורמות

  • Meta: פיקסל בדפדפן + Conversions API מהשרת (הרבה בוני אתרים ו-CRM מציעים חיבור מוכן). השילוב מחזיר המרות שחוסמי פרסומות ו-iOS ״מעלימים״.
  • Google Ads: מעקב המרות דרך התג או ייבוא מ-GA4. Enhanced conversions משפר דיוק.
  • הסכמה לקוקיז (Consent Mode) — באתרים שפונים לאירופה זו חובה, ומשפיעה על המדידה.

בדיקה לפני קמפיין — 5 דקות

  • פתחו את האתר ובצעו המרה אמיתית (ליד בדיקה).
  • GA4 ← דוח בזמן אמת / DebugView: האירוע מופיע?
  • Meta ← Events Manager ← Test events: האירוע מופיע?
  • Google Ads ← סטטוס פעולת ההמרה ״פעיל״/״מקליט״.
  • סמנו את ליד הבדיקה כ״בדיקה״ ב-CRM.

דוגמה מהשטח

לידים כפולים

Meta הראתה 120 לידים, ב-CRM היו 64. הסיבה: האירוע נשלח גם בטעינת עמוד התודה וגם בלחיצה על הכפתור. אחרי תיקון — Meta הראתה 66, והאלגוריתם התחיל לייעל לפי לידים אמיתיים. ה-CPL האמיתי ירד ב-20% תוך שבועיים.

3 שאלות

1. מה נקרא היום ב-GA4 ״אירוע מפתח״?

Key events הם מה שבעבר נקרא ״המרות״ ב-GA4.

2. Meta מראה 100 לידים, ה-CRM מראה 70. מה מקור האמת?

הכסף והלקוחות נמצאים ב-CRM. בודקים את הפער ומחפשים כפילויות.

3. למה מחברים Conversions API בנוסף לפיקסל?

השרת שולח את האירוע גם כשהדפדפן חוסם.

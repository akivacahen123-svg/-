API וחיבור בין מערכות — מאפס

להבין מה קורה כשמערכת אחת ״מדברת״ עם אחרת — ולחבר בלי להיבהל.

בסוף השיעור תדעו

  • להבין API, Webhook ו-JSON במילים פשוטות
  • למפות את זרימת הליד בין המערכות שלכם
  • לבנות חיבור ראשון בכלי ללא קוד
השורה התחתונה

API הוא מלצר: אתם מבקשים, הוא מביא מהמטבח. Webhook הוא פעמון: המטבח מצלצל לכם כשהמנה מוכנה.

שלושה מושגים

  • API — דלת מסודרת שדרכה מערכת אחת מבקשת או שולחת מידע למערכת אחרת. (״תביא לי את כל הלידים מהיום״)
  • Webhook — הודעה אוטומטית שנשלחת כשמשהו קורה. (״נכנס ליד חדש!״)
  • JSON — הפורמט שבו המידע נשלח. פשוט רשימה של שדה וערך:
{ "name": "דנה", "phone": "0501234567", "utm_source": "facebook" }

זהו. כל השאר הוא פרטים.

מפת הזרימה של ליד

לפני שמחברים — מציירים. לכל ליד:

  • מקור: טופס באתר / טופס מיידי בפייסבוק / וואטסאפ / טלפון.
  • יעד: CRM, גיליון, מייל, וואטסאפ לאיש המכירות.
  • שדות: שם, טלפון, מייל, UTM, שם הקמפיין, תאריך.
  • מה קורה בכישלון: מי מקבל התראה אם החיבור נשבר?

לחבר בלי מתכנת

כלים ללא קוד כמו Make, Zapier או n8n בנויים כך:

  • טריגר (Webhook / ״ליד חדש בפייסבוק״) ←
  • פעולות (הוסף ל-CRM, שלח הודעה, עדכן גיליון).

רוב מערכות ה-CRM ובוני האתרים כבר מציעים חיבור מוכן ל-Meta Lead Ads ולטפסים. התחילו ממה שמוכן.

טיפנקודת התורפה: חיבורים נשברים בשקט (טוקן שפג, שדה ששונה). קבעו בדיקה שבועית או התראה על כישלון.
דוגמה מהשטח

לידים מפייסבוק שהלכו לאיבוד

עסק הוריד לידים מטפסים מיידיים פעם ביום, ידנית, לקובץ אקסל. ליד חיכה בממוצע 14 שעות. אחרי חיבור דרך Make: ליד נכנס ל-CRM ונשלח לאיש המכירות בוואטסאפ תוך פחות מדקה. אחוז היצירת קשר עלה מ-45% ל-80%.
